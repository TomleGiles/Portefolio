Incidents & post-mortems

INC-01 · Control plane

The cluster deadlocks itself on restart

Symptom
master-1 unreachable, unstable API server, cluster running degraded.
Diagnosis
Undersized node: the OOM killer takes out etcd and quorum drops to 2/3. rke2-server waits on kubelet, which waits on the etcd static pod, which no longer starts. Deadlock.
Fix
rke2-killall to break the loop, a clean node restart, then resizing the master.
Lesson
A control plane is not sized like a worker. etcd's resources are an availability constraint, not a line item to trim.
INC-02 · Backups

Three weeks without backups, and the jobs were green

Symptom
No recent snapshot in the repository. The backup jobs kept reporting success.
Diagnosis
S3 quota full at 500 GiB. The restic repository held 486 GiB across 349 snapshots that were never pruned: the dump name embedded the date, so every backup created its own group and the retention policy applied to nothing.
Fix
Upgraded restic, forget --group-by host then prune: 486 → 48 GiB. Script hardened with set -euo pipefail and a stable dump name.
Lesson
A green job proves nothing. What you monitor is the age of the last restorable snapshot — not the cron's exit code.
INC-03 · Vault

The unseal chain eats its own tail

Symptom
Audit of Vault's startup chain, carried out after a platform restart.
Diagnosis
The primary Vault's transit auto-unseal depends on a secondary Vault, Shamir-sealed and deployed as a single replica. If the secondary goes down, nothing unseals — including the secrets needed to bring it back.
Fix
SPOF identified, documented and added to the backlog with its exit options. [TODO: remediation status]
Lesson
A circular startup dependency is invisible in steady state. You find it the day everything restarts at once.

Ipsos — Global BI

Ipsos — rebuilding the Excel export engine

Sept 2025 – Jan 2026
Context

A C# / ASP.NET financial portal used by management controllers in more than 90 countries. The Excel export engine threw OutOfMemoryException past 50,000 rows.

Role

Software Developer, Global Business Intelligence. Team spread across Europe / North America / India, work in English, Jira, agile.

Stack
C# · ASP.NET · IIS · SQL Server · Open XML SDK (SAX mode) · EPPlus (V1) · Python
What I did

Diagnosis: double allocation across DataTable + EPPlus and Large Object Heap fragmentation — 3 to 4 GB of memory for 50 MB of data. Rewrote as pure streaming: Open XML SDK in SAX mode, IDataReader in SequentialAccess, direct FileStream writes, a single indexed stylesheet, no-allocation parsers, two-pass predictive auto-fit, .xlsx recompression.

Outcome

Memory flat at 100–200 MB. 1 million rows in ~2 min where V1 crashed at 45 s. OOM incidents disappeared from the production logs, and files are 20–30% smaller.
